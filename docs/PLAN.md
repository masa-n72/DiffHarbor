## 1. ゴール

macOS と Windows で使う WinMerge 風の比較・マージツールを、Rust と gpui で作る。
見た目の目標は WinMerge のファイル比較画面とする。

- 白背景の明るい配色
- 左右 2 ペインと、左端の位置ペイン
- 差分行は黄色、行内の変更箇所は濃い黄色、相手側にない行は灰色
- ペインごとのステータスバー（行、桁、文字コード、改行コード）

結果: 自動テストと、アプリ上の実行の両方で確認した。UTF-8 と Shift_JIS のサンプルで全差分を右へコピーして保存し、右のファイルが Shift_JIS、CRLF のまま左と同じ内容になった。

アプリ上で確認した動作。

| 操作 | 結果 |
|---|---|
| 差分 1 件を右へコピー | 差分が 3 件から 2 件に減り、「元に戻す」と「保存」が有効になった。ファイルは保存前なので未変更 |
| 全差分を右へコピーして保存 | 差分 0 件。「保存しました: right.txt」と表示。ファイルは Shift_JIS、CRLF のまま |
| 保存後に元に戻す | 差分 3 件に戻り、右に未保存の印（●）が付いた。「やり直す」が有効になった |
| 右を UTF-8 で開き直す | 文字化けして表示され、「変換できない文字があります（保存できません）」と表示 |

実装時に決めたこと。

- マージの履歴は diff-core に置き、画面なしでテストする
- 履歴は行の差し替えだけを記録する。ファイル全体の写しは持たない
- 未保存かどうかは、内容の版と保存時の版を比べて判定する。保存後に元へ戻すと未保存になる
- 未保存の確認は「保存」「保存しない」「キャンセル」の 3 択
- 別のファイルを開く時は、開く対象を選んだ後に未保存を確認する
- 開き直しは、その側の変更だけを確認の対象にする。開き直すと履歴は消える
- 保存時のバックアップ（.bak）は作らない
- 未保存の印（●）はパスの先頭に付ける

ユーザーに確認してほしい操作。

- ツールバーの各ボタンと、中央の「›」「‹」ボタン
- ⌘S、⌘Z、⇧⌘Z、⌥→、⌥← のキー操作
- 「ファイル」「差分」「文字コード」メニュー
- 未保存の状態でウィンドウを閉じた時の確認ダイアログ
- 「左を別名で保存…」「右を別名で保存…」

確認用の環境変数（デバッグビルドのみ）: `DIFFHARBOR_DEBUG_ACTIONS=copy_all_right,save` のように、起動後に実行する操作を並べられる。

## 6. 進め方

- M1 から順に進める。各マイルストーンの完了時に、この文書のチェックと「現状」を更新する
- 仕様の変更は spec-text-compare.md に反映してから実装する
- ロジックは diff-core に置き、単体テストを付ける。画面側にロジックを置かない
- マイルストーン単位で git にコミットする（コミットは依頼があった時のみ）
- macOS と Windows の間でフォルダをコピーして作業を続ける場合は、`git config core.fileMode false` にする（実行権限の差で全ファイルが変更扱いになるため）
