# DiffHarbor 開発計画

最終更新: 2026-11-14

この文書を作業の基準にする。マイルストーンを終えるたびに、チェックと「現状」を更新する。
画面と動作の細かい期待結果は [spec-text-compare.md](spec-text-compare.md) に置く。

## 1. ゴール

macOS で使う WinMerge 風の比較・マージツールを、Rust と gpui で作る。
見た目の目標は WinMerge のファイル比較画面とする。

- 白背景の明るい配色
- 左右 2 ペインと、左端の位置ペイン
- 差分行は黄色、行内の変更箇所は濃い黄色、相手側にない行は灰色
- ペインごとのステータスバー（行、桁、文字コード、改行コード）

## 5. 段階 1 のマイルストーン

### M1 差分エンジン（画面なし） 完了 2026-11-14

差分と入出力を `crates/diff-core` に分離し、画面なしでテストできるようにする。

- [x] Cargo ワークスペース化（`crates/diff-core`、`crates/app`）
- [x] 未使用の依存（`walkdir`、`rfd`）を削除
- [x] 読み込み: BOM、UTF-8、Shift_JIS、EUC-JP の判定
- [x] 読み込み: バイナリ、UTF-16、ISO-2022-JP は未対応としてエラーにする
- [x] 改行コード（LF、CRLF、混在）と末尾改行の保持
- [x] 保存: 変換できない文字があれば中止（行番号を表示）
- [x] 保存: 一時ファイルに書いてから置き換える。権限を保持
- [x] 行差分と差分ブロック（試作から移設）
- [x] 行内のトークン差分（英数字は語単位、日本語は 1 文字単位）
- [x] 確認用 CLI `dhdiff`（2 ファイルを比較して端末に表示）

完了条件: `cargo test --workspace` が通る。CLI で UTF-8 と Shift_JIS のファイルを比較し、差分が正しく出る。
結果: テスト 24 件通過。`samples/ja` の UTF-8 と Shift_JIS の比較で、3 件の差分と行内の変更箇所が正しく出た。

実装時に決めたこと。

- 文字コードの推定は、UTF-8 として妥当でない場合だけ行う。日本語の文字コードを優先する
- 推定した場合は「Shift_JIS (推定)」のように表示する
- 読み込み時に変換できないバイトがあった場合、表示はするが保存を拒否する
- シンボリックリンク経由の保存は、リンクを残してリンク先を置き換える
- 読み取り専用ファイルへの保存は、置き換えずにエラーにする

画面の確認方法。

- 作業環境から `screencapture` で撮影し、アプリの領域だけを切り出して確認する
- 環境変数 `DIFFHARBOR_BOUNDS="x,y,幅,高さ"` で、ウィンドウの位置と大きさを固定できる
- 作業環境からはクリックやキー入力を送れない。操作の確認はユーザーが行う
- メニューバーは切り出しに写らず、メニューの表示は未確認

## 6. 進め方

## 8. ビルドと実行

アプリの起動。

```bash
cargo run -- samples/ja/left_utf8.txt samples/ja/right_sjis.txt
```

全テスト。

```bash
cargo test --workspace
```

確認用 CLI。

```bash
cargo run -p diff-core --bin dhdiff -- samples/ja/left_utf8.txt samples/ja/right_sjis.txt
```
